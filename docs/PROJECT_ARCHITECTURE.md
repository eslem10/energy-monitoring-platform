# Smart House Project Architecture

This project is organized around one shared backend and two frontends:

```text
mqtt-reception/
  index.js                  Node.js entry point
  src/                      Node.js backend source
  web-dashboard/            React web dashboard
  smart_house_mobile/       Flutter native mobile app
  chatbot-backend/          FastAPI chatbot backend
  data/                     Local runtime JSON state, ignored by git
  mcp_*_mqtt.py             Python collectors / MQTT bridges
  mqtt_device_bridge.py     Generic Python MQTT bridge
  mcp_*_data/               Local captured measurement files
  mobile-app/               Old Expo prototype, optional/archive
```

## Runtime Architecture

```text
STM32 / measurement scripts
        |
        v
Python collectors publish MQTT
        |
        v
MQTT broker: broker.emqx.io
        |
        v
Node.js backend
  - MQTT ingestion
  - InfluxDB writes/queries
  - REST API
  - device registry
  - auth
  - alerts history
  - app settings/scenes/favorites
        |
        +--> React web dashboard
        +--> Flutter mobile app
        +--> FastAPI chatbot integration
```

## Backend

```text
index.js
src/
  config.js                 Environment configuration
  server.js                 HTTP server + static dashboard serving
  routes.js                 REST API routes
  http.js                   JSON helpers
  services/
    mqttService.js          MQTT subscribe/control publish
    influxService.js        InfluxDB write/query/statistics
    deviceRegistry.js       Devices registry
    authService.js          Login/register with hashed passwords
    alertHistoryService.js  Saved notifications history
    appStateService.js      Budget, tariff, favorites, scenes
    assistantService.js     Assistant backend/fallback logic
```

Main backend command:

```powershell
node index.js
```

## Runtime Data

```text
data/
  users.json                Registered users
  devices.json              Device registry
  alerts.json               Alert/notification history
  app-state.json            Settings, scenes, favorites
```

`data/` is ignored by git because it is local runtime state.

For Docker/cloud deployment, persist this folder with a volume if you want users/settings/history to survive container restarts.

## Files That Are Optional Or Legacy

```text
mobile-app/                 Old Expo app prototype
mobile_main_diff.txt        Temporary diff/debug file
web-dashboard/monolithic.html
web-dashboard/index_restored.html
web-dashboard/index_restored_utf8.html
```

Keep them during development if you still need references. Before final deployment, they can be archived outside the production image.

## Deployment Units

Recommended Docker services:

```text
backend-node                Node.js API + MQTT ingestion + serves web build
influxdb                   Time-series database
chatbot-backend             FastAPI chatbot, optional
```

The Flutter mobile app is built separately as an APK/web build and connects to the Node API URL.
